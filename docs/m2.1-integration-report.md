## 2. Issues Found

### 2.1 Scan History: "Couldn't load your scans" (HTTP 500)

**Symptom:** Scan History rendered its error state instead of the list.

**Root cause — the dev database was at the M1 migration.** The running backend
(`backend/neuroplant.db`) was at Alembic revision `e7a4341cf99e` (M1). The M2
migrations (`5c9a2e7f41b0` scans table, `a3f9c8b2d1e4` soft-delete/audit) had
never been applied to it, so `GET /scans` failed with
`no such table: scans` → HTTP 500. This was an **environment/boot issue, not a
frontend or API bug.** Reproduced live against the running server, then
in-process via `TestClient` to capture the SQLite traceback.

**Fix (ops):** `alembic upgrade head` → database now at head
`a3f9c8b2d1e4`. Verified `GET /scans` returns 200.

### 2.2 Media URLs 404 (images + Grad-CAM heatmaps would never load)

**Symptom:** `LocalStorageService.url()` returns `/media/{key}` but nothing
served those paths — upload previews, scan images, and heatmaps would 404.

**Root cause:** `app/main.py` mounted no static file handler for `/media`.

**Fix (code):** When `storage_provider == "local"`, the app now mounts
`/media` onto the local storage root (`check_dir=False` so boot works before
the directory exists). Added the `/media` forward to the Vite dev proxy and a
backend test (`test_media_serving.py`, 2 tests). **Requires a backend restart
to take effect** — the running dev server was not started with `--reload`.

### 2.3 Frontend: no access-token refresh on 401

**Symptom:** An expired access token would fail authenticated requests
permanently (e.g. after a long session, scans/profile would error) instead of
refreshing.

**Fix (code):** `lib/api.ts` now performs a **single-flight refresh** on 401:
`POST /auth/refresh` (existing endpoint), stores the new tokens, and retries the
original request once. `FormData` bodies skip `Content-Type`/`JSON.stringify`
so multipart uploads stay correct.

### 2.4 Profile button did nothing / no Profile page

**Symptom:** The header user chip was a plain `<span>` — not a link.

**Fix (code):** It is now a button linking to a new `/profile` page, which
renders identity, account details, total scans, and an inline name editor wired
to `PATCH /users/me` (existing endpoint). See §3.3.

### 2.5 Deferred features showed broken/blank states

**Symptom:** `/assistant`, `/doctor`, `/marketplace` routes were missing or
rendered "Coming Soon" with no explanation of *what* was coming or *when*.

**Fix (code):** A single `ComingSoonPage` now tells the user the feature is
planned and in which milestone, plus a list of planned capabilities and a
"Back to home" action. Milestones taken from `docs/09-milestone-timeline.md`:
Crop Doctor → **M3**, AI Assistant → **M4**, Marketplace → **M6**.

### 2.6 Home CTA dead-ended

**Symptom:** The landing page "Ask the AI assistant" CTA linked to `/register`
(the old flow) instead of the assistant.

**Fix (code):** Now links to `/assistant` (the proper coming-soon page).

## 3. Fixes Applied

### 3.1 Scan Crop page (`frontend/src/pages/scan-crop.tsx`, NEW)

Replaces the `/detect` placeholder with a real scan flow that reuses the
existing backend end-to-end:

- **Photo source** — upload picker and camera capture (`capture="environment"`
  opens the camera on mobile), with object-URL preview and revoke-on-replace.
- **Crop + plant part** — crop options from `GET /catalog/crops`, part from the
  `leaf|fruit|stem|plant|whole` set.
- **Submit** — `POST /scans` (multipart, existing endpoint) with a generated
  `client_scan_id`; invalidates the `["scans"]` cache so the new scan appears in
  History immediately.
- **Result view** — disease name, confidence & severity badges, crop/part/
  stage rows, AI explanation, confidence advice, Grad-CAM heatmap
  (`explain.overlay_url` served via `/media`), top-5 ranked predictions with
  progress bars, and links to the full report / history / scan-another.
- **States** — sign-in required, submitting (spinner), error with a readable
  message + Try again.

### 3.2 Scan History fixed

The migrations issue (2.1) plus the refresh-on-401 hardening (2.3) restore
history loading. The page itself needed no frontend changes — the failure was
server state + token lifecycle, both addressed.

### 3.3 User Profile page (`frontend/src/pages/profile.tsx`, NEW)

Route `/profile`, linked from the header user chip:

- Identity card with avatar placeholder, name, role, and an inline **Edit
  Profile** flow (name → `PATCH /users/me` → syncs the zustand store, shows a
  transient "Profile updated." confirmation).
- Account details: name, phone, email, role, member-since (localized date).
- Activity: total scan count (`GET /scans?page=1&page_size=1` → `total`) with
  links to Scan History and Scan a Crop.

### 3.4 Coming Soon pages (`frontend/src/pages/coming-soon.tsx`, REWRITTEN)

One parameterised component (`navKey`, `milestone`, `icon`) drives `/doctor`,
`/assistant`, and `/marketplace`: badge, feature title, what's-coming body,
planned-capabilities list, "Planned for Milestone N" pill, and a Back-home
button. No dead links remain.

### 3.5 Language architecture (`frontend/src/i18n.ts`)

Prepared for future languages without faking any: a declarative `LANGUAGES`
registry (`code`, `nativeName`, `enabled`) is the single source of truth; the
switcher and i18next resources are both derived from it. New languages = one
locale pack + one registry entry. Only **en** and **hi** are shipped; no
machine-translated or invented languages were added.

### 3.6 Media serving (`backend/app/main.py` + `backend/app/services/storage.py`)

`local_storage_root()` centralises the storage path; `/media` is mounted as
`StaticFiles` (local provider only) so upload images, processed images, and
heatmaps are served. Backend test added.
