# M3.1 Report — Conversational Multilingual AI Assistant Upgrade

**Milestone:** M3.1 (post-M3 upgrade) · **Date:** 2026-08-06
**Branch:** `main` · **Status:** ✅ Complete

---

## 1. Summary

M3.1 turns the M3 rule-based intent *matcher* into a **conversational,
multilingual AI assistant** — without rebuilding it. The assistant no longer
falls back to *"I couldn't find an answer"*; instead it holds a real dialogue:

- **Natural conversation** — time-aware greetings ("Good morning, farmer…"),
  identity ("Who are you?"), help, thanks, small-talk, and polite handling of
  off-topic questions ("I specialize in crop and farming guidance…").
- **Follow-ups with context** — "My tomato plant has early blight" →
  "How do I treat it?" → "Is it dangerous?" → "How long will recovery take?"
  resolves pronouns and remembered subjects across turns.
- **Natural farming questions** — "My leaves are yellow", "Why is my crop
  dying?", "How often should I water?", "Can I use neem oil?", "Which fertilizer
  is best?", "Explain in simple words."
- **Project-aware answers** — every agricultural reply is *built from existing
  engine data* (scan history, disease prediction, treatment catalog, soil plan,
  crop doctor / recovery tracker, crop calendar, user profile). **No engine
  logic was duplicated.**
- **Language integration** — the UI language selects the reply and speech
  language (English ⇄ हिन्दी), reusing the existing en/hi i18n split; the
  architecture is ready for more languages.
- **LLM-ready** — a clean `ConversationProvider` interface with a local
  rule-based provider and an optional Anthropic provider behind the same
  protocol (User message + conversation history + scan + treatment + soil +
  calendar + recovery snapshot).
- **Conversation memory** — per-user, DB-backed chat history (restored on page
  reload, follow-up context, clear-chat clears the server transcript too).
- **UI polish** — welcome/suggestions, typing indicator, timestamps, intent
  badges, clear-chat, reading-aloud controls; accessible throughout.

The M3 milestone release `v0.3.0-m3` remains the released version; M3.1 lands
on top of it without a new tag.

## 2. Architecture

### Backend — provider/adapter pattern (mirrors the `DiseaseClassifier`/`ModelRegistry` precedent)

```
assistant.py  (thin facade: AssistantService)
   │  resolve lang → load history → build AssistantContext → _answer_safely
   ▼
ConversationProvider (Protocol)          ← select_conversation_provider(settings, db)
   ├── LocalConversationProvider          (default; fully offline, 19 intents)
   └── LLMConversationProvider            (optional; Anthropic Messages via httpx)
   │
   └── ConversationService  →  ConversationMessage  (per-user rolling transcript)
```

**Key pieces**

- **`assistant_context.py`** — language helpers (`pick(lang, en, hi)`,
  `detect_lang` via the Devanagari range), time-aware `greeting_for(lang, hour)`,
  `CatalogEntityExtractor` (catalog crop/disease names, sorted longest-first,
  async-loaded once), `ConversationMemory` (seeded from history, `remember`,
  `resolve` for anaphora), and `AssistantContext` (user, query, lang, history, now).
- **`assistant_providers.py`** (≈1,660 lines, the conversational engine) —
  a 19-intent bilingual keyword table routed by `_detect_intent`; `_is_statement`
  catches declarative reports ("My leaves are yellow"); `_has_agri_hint`
  rescues questions that are agricultural but miss a keyword; and one builder
  per intent (`_reply_disease`, `_reply_treatment`, `_reply_soil`, `_reply_recovery`,
  `_reply_recovery_timeline`, `_reply_calendar`, `_reply_fertilizer`,
  `_reply_watering`, `_reply_neem`, `_reply_report`, …) that **reuse the M2/M3
  engine services directly**:
  `ScanService.list_scans`, `RecommendationService.for_disease/for_scan`,
  `SoilRecommendationService.for_disease/for_scan`, `RecoveryTrackerService.tracker`,
  `CalendarService.dashboard`. Every reply is generated in the request language
  through bilingual builder helpers.
- **Anaphora resolution** — `ConversationMemory` seeds the remembered subject
  from the last N history turns, so "it" resolves to the disease named in the
  previous turn; explicit mentions override the memory.
- **`conversation.py` + `models/conversation.py`** — DB-backed memory with a
  rolling window (`CONTEXT_WINDOW=20` for context, `MAX_MESSAGES=60` cap with
  trim) so transcripts stay bounded; `list()` returns newest-`limit` rows in
  chronological order.
- **`assistant.py` (facade)** — resolves the request language (explicit, else
  detected), loads history, builds the context, calls the provider through the
  protocol, and **persists both turns** — user and assistant — via
  `ConversationService.append` in one transaction. If the LLM provider is
  unconfigured or errors, it falls back to `LocalConversationProvider` — the
  assistant never dies.

### Frontend

- `types/assistant.ts` — `AssistantIntent` union grown to 19 intents;

- `lib/api.ts` + `services/voice-assistant.ts` — `getAssistantConversation()`

## 3. Conversation Behaviour

| Intent | Example | Behaviour |
|---|---|---|
| greeting | "Hello" / "नमस्ते" | Time-aware bilingual greeting |
| identity | "Who are you?" | Explains the assistant + what it can do |
| help | "What can you do?" | Lists the farming topics it covers |
| thanks / smalltalk | "Thanks!" / "Ok" | Warm ack, keeps context |
| disease | "What does my crop have?" | Detects the disease (uses scan history if present) |
| explainer | "What does this mean?" / "Is it dangerous?" | Plain-language explanation + severity/risk |
| symptoms | "My leaves are yellow" | Recognises symptom statements (no "?" needed) |
| treatment | "How do I treat it?" | Treatment plan from the versioned catalog |
| fertilizer / watering / neem | "Which fertilizer?" / "How often to water?" / "Can I use neem oil?" | Curated guidance |
| soil | "How's my soil?" | Soil-health score + plan |
| recovery / timeline | "How long will recovery take?" | Recovery tracker status + timeline |
| calendar | "What should I do today?" | Today's calendar tasks |
| report / answer | "Noted" / direct facts | Acknowledges / answers |
| non_agriculture | "What's the weather?" | **Polite specialization boundary** — never "I couldn't find an answer" |

## 4. Fallback behaviour (explicit requirement)

Non-agriculture questions get a **polite specialization reply**: the assistant
explains that it focuses on crop and farming guidance and invites a farming
question — in the request language. The string *"I couldn't find an answer"*
no longer exists in the assistant code path.

## 5. Conversation memory

- Every turn is persisted per user (`ConversationMessage`), so a page reload
  restores the full transcript (badges + speech locale included).
- Follow-ups stay in context via the seeded `ConversationMemory`.
- Clear-chat deletes both the local view **and** the server transcript.
- Windows/session bounds: `CONTEXT_WINDOW=20` messages feed each answer;
  transcripts are trimmed at `MAX_MESSAGES=60`.

## 6. Language integration

- `detect_lang(query)` uses the Devanagari range — a Hindi query asked in an
  English UI is still answered in हिन्दी; the UI language otherwise picks the
  language, and `speechLocale` maps it to `en-IN` / `hi-IN` for voice output.
- All builders are bilingual via `pick(lang, en, hi)`; the intent-keyword table
  covers both scripts, and `_kw_match` uses word boundaries for ASCII and
  substring matching for Devanagari (whose combining marks break Python's `\b`).
- Adding a language later = new keyword rows + `pick()` arms; no structural change.

## 7. LLM integration seam

`ConversationProvider` is a one-method protocol (`answer(ctx)`). The local
provider is the default (offline, deterministic, testable). `LLMConversationProvider`
(Anthropic Messages via httpx) is selected when `llm_provider == "anthropic"`
and `llm_api_key` is set; it builds a system prompt, message turns, and a
project snapshot (scan + treatment + soil + calendar + recovery) from the same
engine services. Any failure falls back to the local provider, so the feature
degradates gracefully with no config.

## 10. Known limitations

- **Sections not persisted**: restored assistant turns keep their intent badge
  and language but not the structured section bodies (they aren't in the
  transcript schema) — re-asking regenerates them.
- **LLM provider untested in CI** (requires API key); covered by the local
  fallback instead.
- **Rule-based ceiling**: the local provider handles the 19 intents + follow-up
  memory well, but open-ended general chat is best served by enabling the LLM
  provider.
